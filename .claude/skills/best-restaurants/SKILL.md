# Best restaurants near a location

Runs `scripts/best_restaurants.py` from this repo for the location the user gave and reports the top of the list. The script drives a visible Chrome window through Playwright because Yelp sits behind DataDome, which blocks curl, headless Chrome, and Chrome launched with the usual automation flags. Chrome opens the search page once, and every later page is fetched from inside that page with `fetch()`, spaced four to seven seconds apart

## Steps

1. Take the location from the arguments verbatim, an address like `682 MacArthur Dr, Daly City` or a city like `Santa Barbara, CA`. If the user named something other than restaurants (cafes, bars, ramen), pass it with `--what`. If they named a distance, pass it as `--radius <miles>`; the default is 5 miles around the location, and `--radius 0` lets Yelp pick its own smaller area, which stays capped at 240 results
2. Find the repo root: this skill lives at `.claude/skills/best-restaurants/` inside a checkout of github.com/SwiftWinds/best-sb-restaurants, and when it is symlinked into `~/.claude/skills/`, `readlink -f ~/.claude/skills/best-restaurants` points back into that checkout. Clone the repo if neither exists. From the repo root run `uv sync` once if `.venv` is missing, then `uv run playwright install chrome` only if Google Chrome is not installed (`--channel msedge` and `--channel chromium` also work)
3. Run `uv run scripts/best_restaurants.py "<location>"` and let it finish; a Chrome window opens and closes on its own, so the machine needs a desktop session. A dense area takes a long time (a 5 mile radius around Daly City is a few hundred requests at four to seven seconds each, so well over half an hour) because every tile Yelp caps at 240 gets split into quarters and searched again, so run it detached in the background and check the log instead of waiting on it. It keeps its own Chrome profile under `~/.cache/best-restaurants/` so later runs pass the bot check faster, and if Yelp shows "You have been blocked" it wipes that profile and tries once more. If Yelp shows its captcha mid-run the script keeps reloading the search page with backoff for up to `--max-block-wait` minutes (default 30); the user can solve it in the window, or the block lifts on its own after a while. Progress is saved to `search_pages.json` after every tile, exact count, and batch of coordinates, so if the run gives up or gets killed, run the same command again and it resumes; pass `--fresh` to start over instead
4. Output lands in `results/<location slug>/`: `results.csv` sorted by rating then review count (columns url, name, rating, review_count, review_count_is_exact, price, distance_miles, categories; distance is the straight-line miles from the search center, computed from the coordinates Yelp's map call returns, since Yelp hides per-card distances once a bounding box is passed), `ratings_by_price.png`, and `search_pages.json` with the raw cards per tile. `--out-dir` overrides the folder, `--rebuild` regenerates the CSV and plot from a saved `search_pages.json` without touching Yelp
5. Report the result count, the tile count, and the top few rows. Yelp caps every search at 240, and the 240 are its most relevant matches inside the box re-sorted by rating rather than the highest rated, so the script splits any capped tile until each one is under the cap and unions the tiles; a place can still be missing if its smallest tile is capped (the log says "still capped"). When the user asks about a specific place, search its cuisine with `--what` or check the cards in `search_pages.json`

## Gotchas

- Cards abbreviate review counts above 1000 as `1.9k`. The script fetches each such business page and reads the exact count from its `<title>`, which is what `review_count_is_exact` records
- Yelp's `/search/snippet` JSON endpoint no longer carries organic businesses, so the script parses the server-rendered HTML cards (`[data-testid="serp-ia-card"]`); if the card count on the first page is zero with HTTP 200, Yelp changed its markup and the selectors in `PARSE_CARDS_JS` need updating
- A `403` or `429` mid-run makes the script reopen the search page and retry with growing backoff for up to `--max-block-wait` minutes, so a run that stalls with a captcha in the window needs a human once, not a restart
- Coordinates come from Yelp's `GetMapData` GraphQL call on `/gql/batch`, fifty business ids per request, with the ids read from each search page's embedded JSON. It is a persisted query, so the script reads the current query id from the request the page itself makes; if every distance comes back empty and the log shows HTTP 403 on the map data call, Yelp changed that call and `FETCH_COORDINATES_JS` needs a look. A finished run whose `search_pages.json` has no coordinates gets them filled in by running the same command again, no re-scrape
- The radius becomes Yelp's `l=g:west,south,east,north` bounding box, centered on the map center Yelp returns for the location (read from the distance presets on the loaded page); if Yelp stops rendering those presets the script logs it and falls back to Yelp's default area and its 240 cap
